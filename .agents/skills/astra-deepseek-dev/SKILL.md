# GPT-6.1 Sol + DeepSeek 开发

保留当前会话作为主 Agent。用户指定的主模型是 `gpt-6.1-sol`、medium，Worker 路由是
`custom/deepseek-v4.1-flash`、high，上游模型字段为 `deepseek-v4.1-flash`。
使用现有中转，不改成官方 `deepseek/` 路由，不添加备用模型。
Skill 不会切换会话模型；若当前主模型无法确认或不是 GPT-6.1 Sol / medium，说明这一点，请用户在客户端
选择 GPT-6.1 Sol，思考级别 medium。可先做不依赖模型切换的项目检查，不假报主模型已切换。

## 先确定真实执行方式

读取项目 `AGENTS.md`、相关代码和 Git 状态，确认工作目录、现有修改及验收目标。
检查当前工具 schema 和角色配置，不把磁盘文件当作已加载的派发能力。

- 若当前会话实际提供 `crack_builder` 或明确允许所选 DeepSeek 路由，使用该原生角色，
  检查它固定的模型、provider 和 high，以及该 provider 在当前会话的实际配置层中可用，
  再按可用 schema 派发。不能用另一个 CLI profile 的检查结果代替当前会话检查。已安装且匹配的
  Codex on Crack 可提供原生编排；不猜测 `subagent`、`spawn_agent` 的参数。
- 在本机客户端中，若没有原生 DeepSeek 派发能力，用户调用本技能也授权使用已配置的
  DeepSeek CLI Worker 执行当前开发任务。先说明采用 **CLI Worker**，按
  [客户端执行](references/desktop.md) 检查并调用 `scripts/worker.mjs`。
  它是独立 Codex CLI 会话，不是客户端原生子 Agent，也不继承客户端 MCP/浏览器工具。
  主 Agent 留在客户端负责决策和验收；不启动第二个 GPT-6.1 Sol 来替代它。
- Codex 云端任务读 [云端环境](references/cloud.md)。只能使用当前云端实际可用且
  已配置的 Worker；本机回环地址、登录、进程和技能不会自动转移过去。
  缺少精确路由、网络或认证时，继续规划及只读检查，报告阻塞；不自动换模型或
  声称云端双模型已接通。

## 统一设计、按批次并行、集中验收

Sol 是 Orchestrator，负责整体设计、架构决策、派发、集成和最终验收；DeepSeek 是 Worker，
负责实现、测试、调试与常规修复。忽略用户模板中的示例路径，不假定存在 Pi 的 SUBAGENTS.md
或名为 subagent 的工具；读取当前项目实际存在的指令并使用已经核实的执行方式。

1. **先统一设计。** Sol 先明确目标、约束和验收条件，集中检查相关代码、文档、AGENTS.md
   和 Git 状态。只有影响方案的关键歧义才询问用户，其余作合理假设。复杂任务先完成整体
   方案：模块边界、共享接口、任务划分、依赖关系、写入范围、测试与集成顺序，再开始实现。
   简洁说明方案后，在已有授权范围内直接执行，不逐小步等待用户查看或确认。
   实际发现推翻设计假设时，集中调整受影响的方案再派发，不机械执行失效计划。
2. **统一派发当前批次。** 把所有依赖已满足、互相独立的任务一起启动；优先并行只读探索、
   审查和独立实现，不为并行而过度拆分。默认每批最多两个 Worker，且不超过当前运行时
   并发限制。接口、文件、生成物、数据库、测试端口或其他共享状态有冲突的任务串行执行。
   有上游依赖的任务在上游完成且输出经 Sol 核对后进入下一批，不预先启动等待中的 Worker。
3. **每个委派有完整合同。** 使用 Goal、Context、Scope、Dependencies、Acceptance 五项，
   指定交付物、项目及必要接口、允许读写的路径、上游输出或 none、相关测试与完成条件。
   说明已有用户修改，只给必要上下文，不复制整段会话。Worker 固定现有 DeepSeek 路由/high；
   不根据模板自动升级 xhigh、换成官方路由或添加备用模型。
4. **隔离并行写入。** 优先采用独立 Git worktree，并隔离日志、构建产物和测试资源。
   创建前检查 Git 状态；未提交修改与未跟踪文件不会自动转移，不能丢掉它们所提供的上下文。
   同一目录仅在写入范围、接口和资源明确互不冲突时并行；无法保证时串行。
   Scope 是任务合同，不是额外操作系统沙箱。未经授权不 stash、commit、reset、clean、
   覆盖用户修改或执行破坏性操作。
5. **集中集成和验收。** 不逐步代替 Worker 实现，也不把 Worker 自报完成当作验收。
   Sol 等待该批完成，审查实际 diff、未跟踪文件和测试证据，集成改动并解决接口问题。
   复用可信测试结果，只补做集成检查和具体缺口。最后简洁报告完成内容、真实检查和剩余风险。

Worker 不调用本编排 skill、不继续委派、不更换模型、不改凭据，不自动提交、推送或部署。
轮询超时不等于 Worker 失败，不因此启动替代会话或重叠写入。分析失败后，瞬时故障最多重试
一次；实现修正则汇总反馈给原 Worker，原生会话使用实际跟进工具，CLI 使用记录的 session ID。
部署、发布及其他需要授权的操作沿用已有明确授权；没有授权时先完成可审查结果再请求批准。

## 请求证据

区分“配置正确”“实际请求成功”“中转后端模型身份”。记录实际会话模型、provider、
线程/会话 ID、结果和必要的 Router 脱敏记录。Worker 自称模型或单独 HTTP 200 不足为证。
CLI Worker 的 `isSubagent` 可以为 false；不要把它的独立会话伪装为原生子线程。
安装和预检不调用付费模型；用户给出真实开发任务后才派发。仅要求检查/预览时不推理。
不在聊天、参数、日志、Git 中放密钥，也不自动上传登录文件、个人 profile 或 Router 备份。
报告完成内容、检查结果、实际执行方式、模型证据和剩余问题。
